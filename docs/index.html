squarespace-to-astro

A command-line tool for extracting content and assets from Squarespace sites and creating editable Astro projects.

Current release: v0.5.8

Install Basic use Limitations GitHub

Install

Homebrew is the recommended method on macOS arm64 and Linux x86_64.

brew tap krahd/tap
brew install s2a

Verify the installation:

s2a --help

Homebrew installs the standalone binary and browser dependencies. It does not require a separate Python installation.

Standalone archives and source installation instructions are available in the user guide.

Basic use

Migrate a public Squarespace site:

s2a migrate https://example.squarespace.com \
  --astro-dir ./generated/example-site

Include a Squarespace WordPress XML export when one is available:

s2a migrate https://example.squarespace.com \
  --xml-export ./exports/squarespace-wordpress.xml \
  --astro-dir ./generated/example-site

Run the generated Astro project:

cd ./generated/example-site
npm install
npm run dev

What it does

  • Crawls public Squarespace pages and records site structure.
  • Reads sitemaps, feeds, Squarespace JSON data, and optional XML exports.
  • Downloads Squarespace-hosted assets after confirmation.
  • Creates an Astro project with pages, content, site data, layouts, and local assets.
  • Can generate redirect mappings with --emit-redirects.
  • Can reuse browser session state for account-authenticated content.

The generated project is intended as an editable starting point. Review its layout, navigation, assets, and redirects before deployment.

Authentication

Public sites normally require no authentication. For private content, use the browser-authentication and storage-state options described in the user guide.

The automated browser-authentication flow does not support interactive two-factor authentication.

Limitations

  • Commerce and checkout data are not migrated.
  • Events are not migrated.
  • Forms and form submissions are not migrated.
  • Members-only systems are not migrated.
  • Squarespace administration settings are not migrated.
  • Complex layouts may require manual revision after generation.
