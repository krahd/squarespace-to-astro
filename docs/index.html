Squarespace Migration Tooling

squarespace-to-astro (s2a)

s2a is a command-line tool for extracting content from a Squarespace site and generating an editable Astro project. This page is the quickest path for an end user who wants to install the tool, run a migration, and understand what the generated output looks like.

Current release: v0.5.2. Recent updates add classic-editor component reconstruction in --layout-strategy components, alongside higher-fidelity generation controls, route-based localized asset names, and automatic upgrades for older snapshots that still use hash-suffixed asset filenames.

Before you start

What s2a produces

s2a captures a structured snapshot of a Squarespace site and can turn that snapshot into a buildable Astro project with Markdown or preserved HTML content, route files, layout files, site data, and localized assets under readable route-based filenames.

What you need

You need the site URL you want to migrate, enough disk space for a local output folder, and Node.js only when you are ready to preview or continue editing the generated Astro site.

When to use authentication

Public Squarespace pages can usually be crawled without extra setup. If you need account-authenticated content, s2a can reuse Squarespace login credentials or a saved browser storage state.

Current boundaries

s2a does not migrate commerce, events, forms, members, or full Squarespace admin workflows. Utility routes such as /cart, /checkout, and /account are intentionally excluded from the generated static site.

Install

Homebrew is the recommended install path on macOS arm64 and Linux x86_64: 

brew tap krahd/tap
brew install s2a

If Homebrew is not available for your platform, download a standalone bundle from GitHub Releases and run the bundled s2a executable after unpacking the archive.

Source-based installation and contributor setup are documented in the repository docs. End users normally do not need Python or a separate Playwright install when using Homebrew or the standalone release bundles.

Run your first migration

The simplest migration flow is to point s2a at the public site URL and choose where the generated Astro project should be written: 

s2a migrate https://example.squarespace.com \
  --astro-dir ./generated/example-site

If you have a Squarespace WordPress XML export, include it so s2a can merge that data into the generated project when it improves page or post content quality: 

s2a migrate https://example.squarespace.com \
  --xml-export ./exports/squarespace-wordpress.xml \
  --astro-dir ./generated/example-site

If you omit --output-dir, s2a creates a timestamped run folder under site-output/ and records the main artifacts in execution-metadata.json.

For layout-heavy sites, the current release also supports --fidelity-mode high with either --layout-strategy hybrid or --layout-strategy components. The components strategy rebuilds supported portfolio, gallery, Fluid Engine, and classic-editor layouts into cleaner Astro-friendly markup. Add --markdown if you want Markdown when the conversion stays clean.

Authentication and private content

Public sites do not usually need authentication. For account-authenticated areas, export your Squarespace credentials before running probe, crawl, auth-browser, or migrate: 

export SQUARESPACE_USER=owner@example.com
export SQUARESPACE_PWD=owner-password

s2a migrate https://example.squarespace.com \
  --astro-dir ./generated/example-site
  • --username and --password override the environment variables for a single run.
  • --site-password is only for a site-wide Squarespace password gate. It is separate from account login.
  • The current browser-auth flow does not support interactive 2FA prompts. The Squarespace account used for s2a must have 2FA disabled.

What s2a writes

Run folder

  • execution-metadata.json
  • probe.json
  • site_snapshot.json
  • report.json
  • asset_manifest.json and downloaded-assets/
  • raw-html/ and raw-json/

Generated Astro site

  • migration-manifest.json
  • src/content/pages/
  • src/content/posts/ when posts were detected
  • src/data/site.json
  • public/assets/ for localized media and files
  • src/layouts/ and src/pages/

Continue in Astro

The generated output is a normal Astro project. After migration, move into the generated directory and start the local preview: 

cd ./generated/example-site
npm install
npm run dev

Most hand edits happen in src/content/ for content, src/data/site.json for site metadata and navigation, and src/layouts/ or src/pages/ for the final Astro presentation.

Current limitations

  • 2FA is not supported in the automated browser-auth flow.
  • Commerce, events, forms, members, and full Squarespace admin automation are not migrated.
  • Redirect generation is still pending.
  • The generated Astro project should be reviewed and edited before production use.
